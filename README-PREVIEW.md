# نوبت مارکت — نسخهٔ پیش‌نمایش روی Cloudflare Workers

این پوشه یک **کپی بصری ۱۰۰٪** از پلتفرم نوبت مارکت است که روی Cloudflare Workers اجرا می‌شود.
هدف آن نمایش و تست اسکریپت توسط خریداران است: همهٔ صفحه‌ها، پنل‌ها، فرم‌ها و
جریان‌ها قابل مشاهده و کلیک هستند، اما **هیچ پایگاه داده و منطق واقعی پشت آن‌ها نیست**.

> نسخهٔ اصلی پروژه دست‌نخورده باقی مانده است. تمام تفاوت‌های این نسخه فقط برای
> اجرای بدون سرور (بدون VPS، بدون Postgres) است.

---

## ورود آزمایشی (سه نقش)

در صفحهٔ `/login` یک انتخاب‌گر با عنوان **«ورود به‌عنوان»** اضافه شده است:

| نقش | شمارهٔ پیش‌فرض | مسیر پس از ورود |
| --- | --- | --- |
| مشتری | `09121111111` | `/client/dashboard` |
| هنرمند | `09132222222` | `/artist/dashboard` |
| مدیر | `09991234567` | `/admin/dashboard` |

اطلاعات هر نقش از قبل پر می‌شود؛ کافی است دکمهٔ «ورود» را بزنید.
**هیچ رمزی بررسی نمی‌شود** — هر شماره (با قالب `09xxxxxxxxx`) و هر رمزی پذیرفته می‌شود.
برای عوض کردن نقش کافی است دوباره به `/login` بروید.

## اجرای محلی

```bash
npm install
npm run worker:build      # ساخت بستهٔ Worker با OpenNext (خروجی: .open-next)
npm run worker:preview    # اجرای محلی روی http://127.0.0.1:8788
```

اگر می‌خواهید همین نسخه را با `next dev` ببینید (بدون شبیه‌سازی Worker):

```bash
npm run dev               # http://localhost:3000
```

## انتشار روی Cloudflare

```bash
npx wrangler login        # یک‌بار
npm run worker:deploy     # build + wrangler deploy
```

نشانی نسخهٔ منتشرشده:
**https://nobat-market-preview.mamalisepatipopo.workers.dev**

> نکتهٔ مهم (ویندوز): اگر سرور پیش‌نمایش محلی در حال اجرا باشد، فایل‌های داخل
> `.open-next` قفل می‌شوند و build با خطای `EPERM: Permission denied` شکست
> می‌خورد. برای همین هر سه دستور `worker:build` / `worker:preview` / `worker:deploy`
> اول اسکریپت `scripts/stop-preview.mjs` را اجرا می‌کنند که نسخهٔ پیش‌نمایش قبلی
> را می‌بندد. اگر خواستید دستی این کار را بکنید: `npm run worker:stop`.
>
> OpenNext روی ویندوز رسماً «کاملاً سازگار» نیست و پیشنهاد می‌کند روی WSL اجرا
> شود؛ با این حال در همین پروژه build و deploy و اجرا روی ویندوز بدون خطا انجام شد.

پس از انتشار، آدرس Worker را در صفحهٔ محصول خود قرار دهید. چون این نسخه برای
نمایش داخل صفحهٔ محصول ساخته شده، **محدودیت‌های embed (X-Frame-Options و
`frame-ancestors`) برداشته شده** تا بتوان آن را در iframe هم نمایش داد.

## داده‌های نمایشی

همهٔ داده‌ها در فایل `src/lib/demo/fixtures.ts` تعریف شده‌اند و دقیقاً همان
موجودیت‌های نسخهٔ اصلی را پوشش می‌دهند: کاربران (مشتری/هنرمند/مدیر)، پروفایل و
نمونه‌کار هنرمندان، تتوهای فلش، استودیوها، سرویس‌ها و قیمت‌گذاری، رزروها با
همهٔ وضعیت‌ها، پرداخت‌ها (بیعانه/باقی‌مانده)، نظرات و پاسخ هنرمند، کیف پول و
درخواست برداشت، گفتگوها و پیام‌ها، اعلان‌ها و تیکت‌های پشتیبانی، مجله و
کامنت‌ها، CMS، خبرنامه، پیام‌های تماس، لاگ مدیریت و تنظیمات سیستم.

تاریخ‌ها **نسبی** ساخته می‌شوند (`at(±n روز)`)، بنابراین تقویم و آمار
«امروز/این ماه» همیشه زنده و به‌روز به نظر می‌رسد.

نکته: داده‌ها در حافظهٔ همان نمونهٔ Worker هستند؛ با restart شدن Worker،
همه‌چیز به حالت اولیه برمی‌گردد (رفتار مطلوب برای یک دمو).

## تفاوت‌های عمدی با نسخهٔ اصلی

فقط چهار مورد، همه در لایهٔ زیرساخت — هیچ تغییری در ظاهر و چیدمان صفحات:

1. **پایگاه داده:** به‌جای Prisma + Postgres، موتور درون‌حافظه‌ای
   `src/lib/demo/engine.ts` با همان API (findMany / findUnique / create / update /
   count / aggregate / groupBy / include / select / where) اجرا می‌شود.
2. **احراز هویت:** به‌جای Auth.js، کوکی نشست سادهٔ `nobat-market_demo_session`
   (`src/lib/demo/session.ts`). هیچ رمزی بررسی نمی‌شود.
3. **سرویس‌های بیرونی:** پیامک، ایمیل، درگاه پرداخت و ذخیره‌سازی فایل شبیه‌سازی
   می‌شوند (درگاه در حالت آزمایشی). هیچ درخواست واقعی و هیچ هزینه‌ای وجود ندارد.
4. **خروجی:** به‌جای `output: standalone` برای Docker، بستهٔ Worker با
   OpenNext ساخته می‌شود و بهینه‌سازی تصویر خاموش است.

جایگزینی ماژول‌ها در `next.config.js` (بخش `webpack.resolve.alias`) و
`tsconfig.json` (بخش `paths`) انجام شده تا کد سرویس‌ها و صفحات بدون تغییر کار کند.

## چه چیزهایی «کلیک‌پذیر ولی بدون اثر واقعی» هستند

- ارسال پیام در چت و ثبت اعلان: در همان نمونه ذخیره می‌شود و تا ری‌استارت Worker باقی می‌ماند.
- هیچ کلید واقعی در این نسخه نیست؛ مقادیر `.dev.vars` (کلیدهایی مثل `INTERNAL_API_SECRET`)
  هنگام deploy به‌عنوان رمز نمونه روی Worker ثبت می‌شوند و مقدار واقعی ندارند.
- پرداخت/برداشت/شارژ کیف پول: شبیه‌سازی و بدون اتصال به درگاه واقعی.
- آپلود تصویر: پیش‌نمایش در مرورگر؛ فایلی ذخیره نمی‌شود.
- ثبت‌نام و بازیابی رمز: پیام موفقیت نمایش داده می‌شود (کد/رمز واقعی ارسال نمی‌شود).
